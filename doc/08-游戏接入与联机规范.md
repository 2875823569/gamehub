# 游戏接入与联机规范

版本：1.0 设计基线；本规范中的 SDK 和服务尚未实现。依据 D001、D002、D015—D019。

## 一、接入类型

首发接收 ZIP 格式的 HTML5/Web 游戏，不接收原生安装包或要求平台直接执行的任意系统程序。运行包包含浏览器可运行资源；可编辑工程还包含源码与受支持的构建描述。二者可分别上传并关联同一版本。

单人游戏可提交静态 HTML、CSS、JavaScript 和资源。浏览器可运行的其他构建产物需通过 MIME、设备与资源检查，不因此自动支持 AI 修改。AI 可编辑范围首发限定为标准 HTML/CSS/JavaScript/TypeScript 和平台维护的 Vite 模板；复杂引擎工程、原生插件与作者自建服务器不在自动构建保证范围。

多人游戏必须实现下述平台房间协议及服务端规则接口，不以共享一个页面 URL 作为完成联机。首发运行模型优先支持聚会、回合制和轻量协作游戏；高频物理同步或大型多人世界不作性能保证，按验收与资源上限判断是否接入。

## 二、包结构与清单

根目录必须有 `game.json`，可运行资源放在 `dist/`。可编辑工程额外提供 `src/`、必要的资源与平台支持的构建配置。多人游戏包含 `server/` 规则源码或受支持的编译产物。禁止包含 `.env`、私钥、账号凭据、依赖缓存和系统可执行文件。

`game.json` 至少定义：

- `schemaVersion`：清单版本，首发为 `1`。
- `entry`：运行入口的相对路径，例如 `dist/index.html`。
- `title`、`description`、`instructions`、`cover`：公开元数据。
- `mode`：`single` 或 `multiplayer`；`minPlayers`、`maxPlayers`：人数。
- `devices`：`desktop`、`mobile`；`input`：鼠标、键盘或触屏声明。
- `sdkVersion`：平台 SDK 主版本；`permissions`：申请的能力集合。
- `editable`、`templateId`、`sourceEntry`：可编辑工程的入口及模板标识。
- `serverEntry`：多人规则入口，单人游戏省略。
- `assetLicenses`：素材来源、授权说明及作者声明。
- `saveSchemaVersion`：启用进度保存时的存档结构主版本，修改不兼容结构时必须升级。

游戏 ID、作者 ID、正式版本号、审核结果和资源摘要由平台生成，不能信任上传清单指定的归属或批准状态。

默认限制：压缩包 100 MiB，解压总量 300 MiB，最多 5,000 个文件，单文件 50 MiB，解压倍率不超过 100 倍。均为可调整的初始设计值；超限返回具体原因，不能无提示截断。

## 三、上传与构建检查

规范化路径后拒绝绝对路径、盘符、父目录跳转、符号链接、硬链接、大小写冲突及重复入口；解压时流式限制实际大小和时间，不只信任压缩头。

验证扩展名与实际内容，拒绝嵌套压缩包、直接在宿主运行的系统脚本入口、未知依赖安装指令和任意外部下载；受支持的浏览器 JavaScript 和沙箱规则源码不属于被一概禁止的系统脚本。扫描失败或结果未知保持隔离状态，不能标记为安全通过。

构建只能使用平台模板中的固定命令和批准依赖；不能执行上传 `package.json` 中任意生命周期脚本。依赖经独立受控代理获取并按锁文件校验，构建沙箱没有生产网络、云元数据或平台密钥。

上传、源码、构建输出和审核快照使用内容摘要关联。服务器需要验证上传实际完成、文件摘要和所属账号，不能信任客户端“上传成功”事件。

## 四、浏览器运行边界

平台登录页面与游戏资源使用不同站点，游戏站点不持有平台 Cookie。草稿资源要求短期预览授权，正式游戏也经平台启动鉴权获得对应资源会话。

游戏运行在受限 iframe，默认仅开启脚本能力，禁用顶层导航、弹窗、表单提交、摄像头和麦克风。需要保留真实来源以支持模块等能力的包使用经审核的兼容配置，分配按游戏或版本隔离的来源；不同作者不得共享可互读存储的游戏来源，更不能与平台同源。相关能力须实际兼容验证，不能为了运行而移除所有隔离限制。

平台 SDK 通过专用消息通道提供有限能力。父页面在初始化时校验 iframe 窗口、随机握手标识和预期来源；对于不透明来源不能把字符串 `null` 当作可信身份。后续消息限制协议版本、消息种类、大小和调用频率。

登录令牌、手机号、点数接口凭据不交给 iframe。游戏不能直接调用后台管理、充值或账号修改接口。源码、渲染文本和模型输出均视为不可信数据。

## 五、平台 SDK 设计契约

以下为拟实现接口，供生成模板与接入文档使用：

- `ready(metadata)`：声明加载完成及可用能力；超时显示加载失败。
- `getContext()`：返回公开玩家 ID、显示昵称、房间与版本信息，不含手机号和平台凭据。
- `onState(handler)`：接收当前玩家可见的权威视图及序号。
- `sendAction({actionId, type, payload})`：发送操作，玩家身份由平台附加，不能由游戏伪造。
- `onLifecycle(handler)`：接收暂停、结束、下架、重连和版本提示。
- `reportRoundEnd(result)`：单人游戏报告回合结束；仅作为体验信号，不作为点数或现金奖励依据。
- `saveProgress(data)`、`loadProgress()`：保存限额内进度；登录用户按游戏隔离，游客仅本机保存，清理浏览器数据后不保证找回。

SDK 通过版本协商拒绝不兼容协议；变更须先升级模板与样例，旧已发布版本在明确的兼容窗口内维持可玩。

### 存档契约

单人存档首发为每账号、每游戏、每个存档结构主版本一个槽位，JSON 上限 100 KiB；该数值是可配置初始值。清单新增 `saveSchemaVersion`，写入记录产生档案的游戏版本和修订号，服务端从运行会话取得游戏归属，不能由游戏自由指定其他用户或游戏。

存档读取返回数据及 revision，写入必须附预期 revision，冲突返回明确错误且不覆盖已有云档。存档只作为进度，不作为可信排行榜、支付或奖励依据；多人权威状态仍由房间系统管理。

不同游戏版本只有在声明并经检查保持相同存档结构版本时共享档案。结构不兼容则建立独立槽位并提示旧档保留，不自动丢弃或执行作者提供的任意迁移脚本；通用存档迁移作为后续能力。

游客进度由受信任平台外壳按游戏存储于本地。登录后可由用户明确选择导入当前浏览器的有效存档，要求目标云槽为空，否则保留两者并由用户选择；不得按昵称自动合并或把访客本地结果变成可信成绩。重置需要明确确认并生成新的 revision。

## 六、多人服务器规则

服务器主持权威状态，房主只是大厅管理角色。客户端不能提供随机种子、当前玩家身份、结算结果或完整权威快照来覆盖服务器状态。

规则接口沿用现有 `create`、`act`、`display`、`timeout` 的思路，通过隔离进程 RPC 调用。输入为有限 JSON；上下文提供受控时间、随机数与玩家列表。每次动作以隔离的状态副本执行，成功并校验输出后才提交新序号和状态；异常或超时不得保留半更新状态。`display` 按玩家投影，不能广播完整牌堆、答案或其他人的私有视图。

游戏规则不直接导入 API 或房间网关进程。不可信逻辑在具有资源限制的独立沙箱中执行，禁止访问网络、宿主文件和进程管理接口；超时或输出超限终止执行并记录故障。具体隔离方案见技术架构。

初始上限：每房间最多 8 人、每个操作 16 KiB、单玩家每秒 10 个操作（突发 20）、状态快照 256 KiB、每次规则调用墙钟 500 ms。它们是接入与压测起点，不是经过验证的生产承诺；资源较重的游戏需明确适配，不能让其拖慢其他房间。

## 七、房间、重连与持久化

邀请链接使用不可枚举的随机标识；房间短码仅用于发现，加入仍需服务器授权与限流。房间绑定游戏版本、成员身份及状态：等待、进行中、已结束、已关闭。

开局前允许新成员；进行中默认不允许新玩家加入，平台可对明确支持观战的官方游戏开放只读观战。规则不支持观战时拒绝请求。原有官方游戏的观战和人数行为按适配测试保留。

同一参与者断线宽限初始为 60 秒，重连需证明原身份；另一设备接管会话时撤销旧连接。大厅房主离开可移交管理角色，进行中的缺席处理由已审核游戏规则决定，不能一律改变原有玩法。

房间实例按动作 ID 去重并串行处理，先在沙箱计算候选结果。在持久化提交事务中重新校验当前租约隔离令牌、预期序号和动作 ID，原子保存新状态或已可靠保存的快照引用、事件、去重结果与新序号；提交成功后才向玩家确认。不能只在调用沙箱前检查租约，旧主持的迟到结果在提交时必须被拒绝。

若提交成功但确认消息丢失，客户端重发同一动作 ID，服务器返回已记录的结果而不重新应用动作。未被事务引用的预上传快照按孤立对象清理，不作为恢复依据。恢复失败时明确结束，不用不完整快照继续结算。

## 八、迁移与验收

为现有 12 款官方游戏创建官方作者、元数据和首个不可变版本。复用规则及 UI 时增加 SDK 适配层，不把原有静态注册文件变成用户代码加载器。

逐款验收人数、私有视图、倒计时、断线、房主转移、结束及重开。增加一款独立上传的单人样例和一款独立上传的多人样例，证明平台可以接入新包而不改主站源码。

运行安全设计依据见 [技术选型依据](./17-技术选型依据.md)；这里只定义目标，不能以文档存在替代沙箱攻击测试。
