# 接口契约

状态：拟实现 HTTP 与 WebSocket 契约，不表示当前项目已提供这些接口。统一前缀 `/api/v1`，JSON 使用 UTF-8。

## 一、通用约定

浏览器业务 API 使用安全会话 Cookie，状态修改校验 CSRF 与 Origin；后台使用独立会话与角色授权。UGC iframe 不接收这些凭据，通过受限 SDK 桥接访问游戏能力。

成功响应为 `{data, requestId}`；错误为 `{error:{code,message,details},requestId}`。分页采用游标，默认 20 条、上限 100 条；服务端固定允许的排序字段。

时间为带时区的 ISO 8601，人民币金额为整数分，点数为整数。客户端不得提交可信的作者归属、审核结果、余额或服务端生成的版本状态。

任务、充值订单、退款、人工发点与送审等创建请求要求 `Idempotency-Key`；服务端按用户、路由和请求摘要绑定。相同键与相同载荷返回原结果，相同键不同载荷返回 409。

版本敏感更新提交 `expectedRevision` 或 `If-Match`；版本冲突返回 409，不静默覆盖。幂等记录覆盖业务有效生命周期，过期后也应由任务或订单业务唯一键兜底。

当前内测 API 首先校验测试访问会话，再按操作要求校验站内账号；测试邀请不是账号登录。环境、世代及发布范围由服务端绑定，客户端提交不同范围时拒绝，不能通过 `scope=internal` 绕过公开权限。公开部署不注册模拟支付、固定验证码或内测重置路由。

引导例外：`POST /test-access/exchanges` 不要求已有测试会话，而校验邀请凭证、环境、剩余次数、有效期与请求限流，避免首次进入的循环依赖。最小健康检查不返回业务数据；渠道通知及执行器内部接口使用各自验签或工作负载身份，不要求浏览器 Cookie，也不因此成为匿名业务入口。

## 二、身份接口

- `POST /auth/sms-challenges`：输入手机号、用途及必要的人机验证凭据，返回挑战 ID 和重发等待时间，不返回验证码。
- `POST /auth/sessions`：输入挑战 ID、验证码与注册协议版本，成功设置会话 Cookie；首次注册须有明确同意标识。
- `DELETE /auth/sessions/current`：退出当前会话。
- `GET /me`、`PATCH /me/profile`：读取自己的账号和修改昵称头像。
- `GET /me/sessions`、`DELETE /me/sessions/{id}`：查看并撤销本人设备。
- `POST /me/phone-change`、`POST /me/closure-requests`：换绑与注销受理，返回流程状态，不直接绕过核验。
- `POST /guest-sessions`：在有效测试准入下建立游客会话，当前内测可游玩。未来公开身份策略另行核定，不把未确认的实名流程强加到当前内测。
- `POST /test-access/exchanges`：兑换管理员发放的有限测试邀请，颁发当前环境访问会话；失败不泄露邀请列表。
- `DELETE /test-access/sessions/current`：撤销当前测试访问会话，关联运行授权随之失效。
- `POST /identity-checks`、`GET /identity-checks/{id}`：预留核验流程，只返回本人核验状态与提供方所需的受限跳转信息。

## 三、目录与玩家

- `GET /games`：支持查询词、分类、设备、人数和允许的排序，仅返回当前部署范围内可见的目录；内测游客需测试准入。
- `GET /games/{id}`：当前范围详情；下架返回不可游玩状态与允许展示的说明，不能泄露其他环境内容。
- `POST /games/{id}/play-sessions`：建立单人会话或多人启动授权，核验游戏、版本、地区适用策略、身份与限制，返回平台运行页所需信息。
- `POST /rooms`：输入游戏和当前发布版本引用，服务器重新核验并绑定版本。
- `POST /rooms/{id}/join`：输入邀请凭证，服务端决定参与者身份与席位。
- `POST /rooms/{id}/start`、`POST /rooms/{id}/leave`：房主开局与本人离开；人数和权限以服务器为准。
- `POST /play-sessions/{id}/connection-tickets`：颁发短期、单用途连接票据；票据经受信任父页面使用，不交给游戏源码。

运行资源下载和 WebSocket 接入不接受仅有游戏 ID 的授权。回放、观战和恢复均需验证对应能力。

存档由受信任平台外壳代调 `GET /play-sessions/{id}/save`、`PUT /play-sessions/{id}/save` 和 `DELETE /play-sessions/{id}/save`，目标用户、游戏和结构版本从会话确定。写入/重置要求 `expectedRevision`，超限返回 413，不兼容返回 `SAVE_SCHEMA_MISMATCH`，并发冲突返回 409；游客本地读写不调用云档接口。

`POST /play-sessions/{id}/save-imports` 只在用户明确确认后导入当前持有的访客本地档，校验结构、大小和目标 revision；不提升其结果可信度，目标已有云档不能无提示覆盖。

## 四、作者与版本

- `POST /creator/games`、`GET /creator/games`：创建作品及查看自己的作品。
- `POST /creator/uploads`：声明大小、用途和摘要，返回受限上传目标；平台不得接受任意外部 URL 让服务器抓取。
- `POST /creator/uploads/{id}/complete`：校验实际对象并启动扫描，返回扫描任务引用。
- `GET /creator/uploads/{id}`：查询实际上传、校验状态和关联扫描任务，支持刷新后恢复。
- `GET /creator/artifact-jobs/{id}`：查询本人扫描、检查或导出任务的状态、阶段、失败原因和结果描述。
- `POST /creator/games/{id}/versions`：由已通过检查且归属本人上传或 AI 产物创建草稿。
- `GET /creator/games/{id}/versions`、`GET /creator/versions/{id}`：读取版本与检查结果。
- `POST /creator/versions/{id}/preview-sessions`：作者隔离预览，不能变成可匿名传播的长期公开链接。
- `POST /creator/versions/{id}/submissions`：提交冻结版本及 `publishOnApproval`。
- `POST /creator/submissions/{id}/withdraw`：撤回，要求仍处于可撤回状态。
- `POST /creator/games/{id}/releases`：在当前可信部署范围发布或回滚有效批准版本；内测校验测试目录规则，公开范围才额外校验公开资格。
- `POST /creator/games/{id}/unpublish`：作者主动下架。
- `POST /creator/versions/{id}/exports`：创建导出任务，校验作者权限；完成后通过短期下载授权获取。
- `POST /creator/artifact-jobs/{id}/download-grants`：任务成功且输出未过期时，重新校验归属和限制，发放短期下载授权。链接过期可重新申请；输出已清理返回 `ARTIFACT_EXPIRED` 并提供重建导出入口，不收费 AI 点数。
- `GET /creator/projects/{id}/workspace`：返回工作基线、草稿摘要及 `workspaceRevision`。
- `PATCH /creator/projects/{id}/workspace`：附 `expectedRevision` 保存需求、元数据或选择作者自己的候选基线，冲突时返回服务端当前 revision，不自动合并。
- `GET /creator/projects/{id}/draft-snapshots`：查询本人可恢复快照。
- `POST /creator/projects/{id}/draft-restores`：附目标快照及 `expectedRevision`，生成新草稿并更新工作区；不能原地改写批准版本。
- `POST /creator/games/{id}/archive`、`POST /creator/games/{id}/restore`：归档或恢复处于恢复期内的本人作品；有发布指针时先完成明确下架，恢复不自动重新上架，也不解除平台限制。
- `DELETE /creator/versions/{id}`、`DELETE /creator/games/{id}`：请求软删除，保护引用未解除则返回 `RESOURCE_IN_USE`；返回恢复截止时间及清理状态，不立即物理删除。
- `POST /creator/versions/{id}/restore`：在恢复期限内且文件仍完整时恢复本人软删除版本；已回收返回 410，不重新生成不存在的文件。游戏和版本列表支持只对作者可见的已归档/回收站过滤。

## 五、AI 与点数

- `POST /ai/quotes`：输入需求快照、游戏或基线版本、目标模板，返回报价 ID、点数、有效期、需求摘要和收费说明。
- `POST /ai/tasks`：仅提交确认过的报价 ID；服务端冻结点数，返回任务与余额摘要。
- `GET /ai/tasks/{id}`、`GET /ai/tasks`：查看本人任务，分页或轮询使用有限频率。
- `POST /ai/tasks/{id}/cancel`：仅排队可取消，已执行返回 `TASK_NOT_CANCELLABLE`。
- `POST /ai/tasks/{id}/quality-cases`：提交需求缺陷反馈；不能直接要求接口任意退点。
- `GET /wallet`、`GET /wallet/transactions`：本人余额及可追溯流水。

执行器内部结果接口使用工作负载身份、当前任务租约和执行标识；不能暴露为仅凭任务 ID 可调用的公共成功回调。

## 六、充值与退款

- `GET /billing/products`：返回当前有效档位及规则版本；上线前仅有明确标识的测试商品。
- `POST /billing/orders`：输入商品 ID、规则版本与渠道，返回订单和渠道支付所需参数。
- `GET /billing/orders/{id}`：查询本人订单；支付状态由服务端确定。
- `POST /billing/orders/{id}/refund-requests`：提交本人退款申请及原因，按最终条款受理，不等于立即退款成功。
- `POST /payments/webhooks/wechat`、`POST /payments/webhooks/alipay`：仅处理验签通过的渠道通知；原始请求体须按渠道验签要求保留，不能先任意重编码。

通知使用渠道要求的确认格式，与普通 JSON API 的响应包装分开。重放、金额不匹配、商户不匹配及未知订单需拒绝或隔离核查，不因通知可解析就入账。

## 七、社区与通知

- `GET /games/{id}/comments`、`POST /games/{id}/comments`：读取公开评论及登录发布。
- `POST /comments/{id}/replies`、`DELETE /comments/{id}`：一级回复与删除本人内容。
- `PUT /games/{id}/like`、`DELETE /games/{id}/like`：幂等点赞与取消。
- `PUT /games/{id}/favorite`、`DELETE /games/{id}/favorite`：幂等收藏与取消。
- `POST /reports`、`POST /appeals`：提交举报和申诉，校验对象存在与查看权限。
- `GET /notifications`、`PATCH /notifications/{id}`：本人消息及已读。
- `POST /test-feedback`、`GET /test-feedback/{id}`、`POST /test-feedback/{id}/retests`：持有效测试会话的提交者创建、查询和复测本人问题；前台不能自定处理状态或替别人关闭。允许的附件先经过受限上传与扫描。
- `POST /test-feedback/uploads`、`POST /test-feedback/uploads/{id}/complete`、`GET /test-feedback/uploads/{id}`：受控游客或账号上传并查询自己的反馈附件，默认仅 PNG/JPEG 和脱敏文本，单文件 5 MiB；关联测试会话，扫描通过后才能绑定反馈，不能复用作者源码上传权限。读取附件经反馈权限校验，禁止公开桶链接。

## 八、后台接口

`/admin/reviews` 提供队列、领取及按版本批准/驳回；`/admin/games/{id}/restrictions` 管理强制下架和明确解除；`/admin/users/{id}/restrictions` 管理账号能力限制。

`/admin/publication-eligibilities` 记录公开资格核查证据与状态；不是平台自行签发外部许可的入口。

`/admin/point-grants`、`/admin/refunds`、`/admin/reconciliation-cases` 分别对应人工发点、资金退款和对账处理；要求理由、权限和适用的复核记录。

`/admin/reports`、`/admin/appeals`、`/admin/configs`、`/admin/audit-events` 对应治理、配置和审计。所有后台接口由服务端鉴权并记录操作。

内测后台另有 `/admin/test-access-grants`（发放与撤销访问）、`/admin/test-feedback`（受理、修复版本及关闭原因）和 `/admin/test-resets`（测试数据重置任务）。重置要求环境核验、影响清单、暂停执行和明确确认，不提供跨环境目标参数；公开部署不暴露这些管理路由。

## 九、WebSocket 与错误

受信任父页面通过一次性票据建立连接。信封包含 `protocolVersion`、`messageId`、`roomId`、`sequence` 和消息体；服务器从连接身份确定玩家，拒绝客户端伪造身份字段。

客户端消息包括准备、操作、确认序号、重连请求；服务器消息包括房间快照、本人视图、操作确认、错误、下架和关闭通知。消息乱序请求重新同步，重复操作按 `actionId` 返回原处理结果。

主要错误：`AUTH_REQUIRED`（401）、`PERMISSION_DENIED`（403）、`IDENTITY_REQUIRED`（403）、`GAME_UNAVAILABLE`（409）、`VERSION_CONFLICT`（409）、`QUOTE_EXPIRED`（409）、`INSUFFICIENT_POINTS`（409）、`PACKAGE_UNSUPPORTED`（422）、`RATE_LIMITED`（429）、`DEPENDENCY_UNAVAILABLE`（503）。错误说明不得泄露其他用户或内部凭据。

本轮补充：`TEST_ACCESS_REQUIRED`（403）、`ENVIRONMENT_MISMATCH`（403）、`RESOURCE_IN_USE`（409）、`SAVE_SCHEMA_MISMATCH`（409）、`ARTIFACT_EXPIRED`（410）、`PAYLOAD_TOO_LARGE`（413）和 `PROVIDER_BUDGET_UNAVAILABLE`（503）。内部成本不足不伪装成用户点数不足。

## 十、契约完成条件

实现阶段由本文件生成 OpenAPI、消息 JSON Schema 和契约测试，覆盖必填字段、尺寸、权限、幂等与所有主要错误；未生成或验证前不能称接口已经可用。
