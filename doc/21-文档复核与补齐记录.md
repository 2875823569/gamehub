# 文档复核与补齐记录

版本：1.1。复核对象是项目文档，不是已经实现的代码。下述“已补齐”表示设计、契约和验收已有说明，不能表述为功能已上线或测试已通过。

本轮依据：用户明确当前仅内测、保留游客免账号游玩，公开上线需要时再调整；继续授权代理完善常规细节，并要求评估值得做的需求。

## 一、内测与公开放行混在一起

原缺口：目录 API 只描述公开内容，预览只允许作者；实施路线又要求 G01—G06 才能完成试运营，导致当前内测不知道采用哪套入口和资格状态。D021 仍写作等待立即确认，与用户最新决定不符。

已补齐：新增内测准入、部署模式、环境世代、内部/公开目录范围及独立支付数据；游客在受控测试范围内可游玩。公开资格继续留作未来门槛，不伪造为已经有效。D021 改为暂缓调整，D022 记录当前阶段，路线新增 B0—B3。

设计位置：[内测范围](./20-内测范围与阶段切换.md)、[发布流程](./05-发布审核及运行流程.md)、[接口](./12-接口契约.md)、[路线](./15-实施路线与交付清单.md)。

验收：INT-01—04、AUTH-01、PUB-04；测试邀请和房间邀请不得互相提升权限，普通客户端无法选择环境或发布范围。

## 二、测试点数不等于真实调用免费

原缺口：预算主要围绕正式收费和付费生成，未完整覆盖测试点数、免费修复、前置对话及供应商超时后的实际费用。

已补齐：用户点数账本与提供方成本预算分离，所有真实调用须有环境预算和预留，未配置则只用模拟服务；超时后先核实真实费用，不能直接退预算再无限重试。真实收款默认关闭。

设计位置：[AI 与账本](./07-AI任务与点数账本.md)、[成本配置](./18-成本模型与初始配置.md)、[数据模型](./11-数据模型与一致性.md)。

验收：AI-10、INT-04—05；免费任务和高额测试点数不能突破真实供应商预算。

## 三、存档能力缺少数据与接口

原缺口：SDK 已承诺保存/加载进度，但未定义存档实体、结构版本、并发写入、重置和游客导入，无法确定游戏升级后如何处理旧档。

已补齐：定义账号/游戏/结构版本槽位、100 KiB 初始上限、revision 比较、云档接口及不兼容旧档保留；游客本机档不按昵称合并，登录后明确选择导入，不直接成为可信成绩。

设计位置：[游戏接入](./08-游戏接入与联机规范.md)、[数据模型](./11-数据模型与一致性.md)、[接口](./12-接口契约.md)。

验收：SAVE-01—02；旧档不因新版结构变化被静默覆盖，两个页面同时保存不丢数据。

## 四、上传和导出异步流程不完整

原缺口：已有创建扫描和导出请求，但缺少查询状态、获取结果、链接过期及刷新后恢复路径。

已补齐：引入通用资源任务对象，补上传状态、任务查询、失败原因、下载授权重发和输出过期处理。获取结果时再次鉴权，不只在发起导出时检查一次。

设计位置：[接口](./12-接口契约.md)、[数据模型](./11-数据模型与一致性.md)、[页面](./09-页面与交互说明.md)。

验收：PKG-08；刷新不丢任务，过期链接可重新申请，别人拿到任务 ID 不能下载源码。

## 五、草稿保存与 AI 结果可能互相覆盖

原缺口：页面可切换工作基线，也允许并行修改，但没有工作区修订与独立更新接口；完成较晚的 AI 结果可能覆盖较新的作者草稿。

已补齐：工作区 revision、不可变草稿快照、自动保存状态、恢复路径、冲突响应和基线切换契约。AI 完成只添加候选版本；报价绑定需求及基线修订，变化时不静默执行新内容。

设计位置：[AI 与账本](./07-AI任务与点数账本.md)、[页面](./09-页面与交互说明.md)、[模型](./11-数据模型与一致性.md)、[接口](./12-接口契约.md)。

验收：DRAFT-01—02；断网、刷新、多标签页和迟到结果均不能静默覆盖已保存内容。

## 六、普通内测故障缺少反馈闭环

原缺口：只有公开举报和 AI 质量退点工单，缺少“某版本白屏、按钮没反应、房间卡住”等普通问题的记录、受理和复测路径。

已补齐：游客测试反馈、版本与环境自动关联、可选择的脱敏诊断、处理等级、修复版本及复测结果。反馈仅在授权范围可见，不作为公开评论，也不自动触发退点。

设计位置：[账号与社区](./06-账号权限与社区.md)、[页面](./09-页面与交互说明.md)、[模型](./11-数据模型与一致性.md)、[接口](./12-接口契约.md)。

验收：FEED-01—02、INT-07；能复现具体版本问题，不能查询他人的反馈或带出私有游戏视图。

## 七、删除和资源回收缺少完整生命周期

原缺口：已有软删除字段及资源保护原则，但没有作者归档、恢复、草稿淘汰、导出包过期和清理时任务仍在执行的具体处理。

已补齐：归档与删除分离、受保护引用、软删除恢复期、明确的临时对象保留时间、回收前二次校验及审计；恢复不自动上架。测试重置先停止入口、处理任务并切换世代，旧结果无法写回。

设计位置：[运维](./14-部署运维与运营手册.md)、[内测切换](./20-内测范围与阶段切换.md)、[模型](./11-数据模型与一致性.md)、[接口](./12-接口契约.md)。

验收：PKG-09、INT-06；删除不能破坏有效版本或证据，重置后旧任务、票据和下载授权失效。

## 八、额外修正与实施前仍需完成的内容

补充停用账号的受限支持入口，解决“普通登录会话全撤销但还需查询订单和申诉”的路径矛盾。补充 `saveSchemaVersion`、环境/范围字段及精确任务终态，避免只新增页面文案却缺服务端约束。

二次复核又补齐三个接口边界：首次测试邀请兑换不要求已有测试会话；软删除游戏/版本都有归属校验及恢复入口；游客反馈附件使用测试会话限定的上传与扫描接口，不借用作者源码权限。这些是上述流程的契约补全，不另扩展产品范围。

本轮修订已进入设计基线；下一步实施仍需生成 OpenAPI/消息 Schema、数据迁移脚本、SDK 示例包和真实测试结果。内测配置值需要测量验证，尚未实现的状态不能写成“通过”。

额外产品增强仅进入 [候选需求](./22-增强需求与优先级.md)，不以文档完善为由直接增加全部功能。
