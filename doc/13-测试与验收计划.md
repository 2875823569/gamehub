# 测试与验收计划

状态：测试计划，尚未执行。本次仅交付文档，不把文档检查计为业务测试通过。

当前阶段执行内测验收；G01—G06 仍为未来公开放行条件，不作为当前游客测试流程的阻塞项。文档 20 的 INT-01—07 为本轮新增基础用例。

## 一、验收方式

每条用例保留环境、构建版本、前置数据、步骤、实际结果、证据链接和结论。正常路径与异常路径都必须通过；账务、越权、未审公开、强制下架绕过及用户代码逃逸为阻断问题。

下列编号是首发最低验收集，实施时拆成自动化用例及人工审核脚本。外部资格和实名决策未完成时，只能在受控测试环境验收相应流程，不把公开付费上线标记为通过。

## 二、账号与权限

- AUTH-01：受邀游客在内测目录免站内账号游玩；创作、评论等受限操作进入登录。公开身份方案另列后续用例，不把内测成功标记为正式实名验收通过。
- AUTH-02：未注册手机号完成验证码及同意注册后只创建一个账号；重复提交返回同一结果。
- AUTH-03：错误、过期和已用验证码被拒绝；号码、IP、设备频率限制生效。
- AUTH-04：更换用户或猜测资源 ID，不能读取他人的源码、AI 任务、钱包、订单、导出文件及审核证据。
- AUTH-05：撤销会话后旧凭据失效；换绑与注销须经身份校验，后台限制不能被重新登录绕过。
- AUTH-06：评论、创作、投稿限制互相独立；账号整体停用会撤销会话，但不自动没收点数或删除账目。

## 三、上传与运行隔离

- PKG-01：有效单人运行包与可编辑工程分别通过接入，显示正确能力。
- PKG-02：路径穿越、绝对路径、符号链接、重复文件、压缩炸弹和超限包在隔离区拒绝，宿主文件不被修改。
- PKG-03：恶意构建脚本不能读取云元数据、生产凭据、宿主网络或其他任务目录。
- PKG-04：游戏不能读写主站 Cookie、调用管理员或点数接口、越权导航或伪造平台消息。
- PKG-05：不透明来源消息伪造、旧 iframe 导航后消息、重放握手及超大消息被拒绝。
- PKG-06：多人规则死循环、内存耗尽和输出超限被终止；其他房间与业务 API 保持可服务。
- PKG-07：独立上传样例无需修改静态注册表即可完成上线流程；缺少可编辑源码的包不显示可用 AI 修改能力。
- PKG-08：扫描和导出任务刷新后可查询终态；过期下载链接可重新获取，输出已清理可重建，越权下载与复用其他环境任务 ID 被拒绝。
- PKG-09：有有效发布、审核、任务、会话或争议引用时不能物理删除；软删除恢复不自动上架，存储清理再次校验引用，任务结束不写入已清理作品。

## 四、AI 与账务

- AI-01：确认需求与固定报价后创建任务，冻结额等于报价且能追溯点数批次。
- AI-02：并发创建超出可用余额的任务，成功任务总冻结不超过余额，失败任务不留下孤立冻结。
- AI-03：排队取消与执行开始同时发生，只能一个状态转换成功；取消成功释放全额。
- AI-04：关页后任务继续，重新登录可见终态；模型重试不重复扣费。
- AI-05：运行检查不通过、平台异常和超时释放点数；之后的迟到成功结果不能重新扣费。
- AI-06：产物保存成功但结算事务失败，可恢复到一致状态，不出现扣费无版本。
- AI-07：需求缺陷核实后免费修复，无法修复退原任务点数；重复处理不重复补偿。
- AI-08：生成可运行但用户新增需求须新报价；审核驳回按责任处理，不能无条件多次退点。
- AI-09：点数到期、任务冻结和退点并发时批次与账户总量一致，付费来源不被错误变成赠送。
- AI-10：测试点数、免费修复、报价前对话同样消耗提供方成本预留；预算不足不发起调用，超时不错误释放尚未核实的外部费用。
- DRAFT-01：断网与刷新后可恢复最近草稿；多标签页同时保存返回冲突，AI 完成不覆盖后来更新的工作基线。
- DRAFT-02：报价后基线变化不静默执行新内容；从历史快照恢复只产生新草稿，不改批准版本和运行中游戏。

## 五、支付

- PAY-01：微信和支付宝各覆盖正常支付、用户关闭页面、回调先后顺序差异和主动查询补偿。
- PAY-02：重复回调、伪造签名、错误商户、错误金额、未知订单和重放不能重复或非法入账。
- PAY-02A：同一渠道交易的不同状态通知可分别记录，重复接收日志不重复入账；退款通知不被原支付交易号的唯一约束错误阻挡。
- PAY-03：订单关闭与迟到支付成功并发，平台能核实并完成入账或退款，不吞款。
- PAY-04：退款申请、渠道成功/失败/处理中、重复通知、部分退款按最终规则一致处理。
- PAY-05：对账产生的差异可追踪到订单、渠道证据、流水及工单，人工修正不改写历史。
- PAY-06：测试环境金额和密钥不能流入生产；正式收费前商品、条款、主体与退款条件已核定。

## 六、发布与下架

- PUB-01：草稿、自动检查失败和待审核版本无法公开启动；可预览不代表公开可玩。
- PUB-02：审核快照文件不可替换；修改标题封面不能绕过复审。
- PUB-03：撤回与批准并发不误发布；审核期间旧版本正常，新版本发布不替换正在进行的对局。
- PUB-04：审核有效但公开资格未核实时不能进入公开目录；内测可按测试范围完成内部发布，公开 API 不能接受内部 scope、审核或测试凭据冒充公开资格。
- PUB-05：主动下架禁止新开局和新成员，原参与者限时完成或重连，超时关闭。
- PUB-06：强制下架后旧链接、缓存启动页、回滚、重连及新版本提交都不能恢复运行权限。
- PUB-07：正常网络下强制下架 5 秒内传达至网关与在线会话；模拟通知丢失后主动校验仍会撤销授权。
- PUB-08：后台解除限制有明确证据与审计，只恢复仍有效批准版本。

## 七、联机与既有游戏

- ROOM-01：人数、准备、房主操作、邀请凭据和版本绑定均由服务端校验。
- ROOM-02：重复、乱序、伪造玩家和频率超限动作不能改变不该改变的状态。
- ROOM-03：每名玩家只收到自己的私有视图；网络抓包与日志中无完整答案泄漏。
- ROOM-04：刷新、断线重连、设备接管及主持进程重启后按序恢复；不能出现两个权威主持同时处理。
- ROOM-04A：沙箱计算中租约转移后，旧主持的迟到提交被拒绝；提交后确认消息丢失，再发同一动作只返回已记录结果，不重复更新状态。
- ROOM-05：逐款验证现有 12 款游戏的玩法、人数、结束、重开、观战和房主离开行为。
- ROOM-06：新增上传多人游戏通过 SDK 完成创建、加入、开局、操作、结束与异常恢复。
- SAVE-01：云档按账号、游戏及结构版本隔离，越权、超限和版本冲突均拒绝；不兼容更新保留旧档，不能静默清空。
- SAVE-02：访客本地档不会自动成为账号云档；明确导入不覆盖已有云档，重置需要确认及预期 revision。

## 八、社区与运维

- SOC-01：点赞/收藏重复请求只计一次，取消后计数正确。
- SOC-02：评论深度、本人删除、作者不能删他人正常内容、举报人身份隔离均生效。
- SOC-03：审核和任务通知可重试，重试不会重复执行业务动作。
- FEED-01：游客仅凭有效测试会话可提交和追踪自己的测试问题，不能浏览他人反馈；选择附带的诊断无令牌和其他玩家私有数据。
- FEED-02：反馈能关联修复版本、等待复测和关闭原因；普通故障不自动变成 AI 退点或公开评论。
- OPS-01：备份恢复演练达到目标，恢复后用渠道交易重新对账，不重复处理未完成事件。
- OPS-02：模型、短信、队列、数据库或对象存储故障时有明确降级和告警，不静默丢任务。
- OPS-03：日志脱敏、后台审计、密钥轮换、配置回滚及紧急停用生成/充值按钮可用。

## 九、容量与发布门槛

初始压测按 100 在线、20 活跃房间、2 并行 AI 任务，记录硬件、包大小、游戏复杂度、网络与测试持续时间。覆盖稳定负载、突发、慢客户端及故障恢复；不能仅凭健康检查通过宣称容量达标。

测量普通 API 和房间操作延迟、CPU/内存、队列等待、失败率、每成功任务实际成本及恢复耗时。未达目标可调整部署或缩小试用配额，不隐去失败结果。

内测放行先满足测试访问隔离、游客游玩、账号权限、沙箱安全、测试账本一致性、真实调用预算及 INT 用例；最小链路可用少量官方与上传样例验证，扩大内测前完成 12 款官方回归。

公开发布另须全部核心回归与迁移验收、容量及恢复演练、G01—G06 证据和对外条款核定。现有 `npm` 测试可作为官方玩法回归基础，不代表新增平台能力已覆盖。
