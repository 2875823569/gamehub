# 本地运行与 cpolar 联机

游戏由这台 Windows 电脑上的独立 Node.js 服务提供，cpolar 是唯一的公网入口。无需云服务器或 Cloudflare 运行环境。

## 日常操作

1. 双击 **启动本地联机.cmd**：构建网页，后台启动 Node.js 房间服务及 cpolar。
2. 用输出的 Public HTTPS 地址进入游戏，将房间邀请链接发给朋友。不要把 `127.0.0.1` 地址发给朋友。
3. **查看联机地址.cmd** 显示最近分配的公网地址；**打开游戏平台.url** 打开本机页面。
4. 玩完双击 **停止本地联机.cmd**。更新代码后先停止再启动。

电脑必须保持开机、联网且不休眠，房主游戏页面需要保持前台。关闭启动命令窗口不会结束后台服务。免费隧道地址可能变化，以每次启动输出为准。

## 连接方式

- 网页资源、创建/加入房间、身份验证、直连协商、在线成员及恢复备份通过 cpolar。
- 正常游戏操作优先通过 WebRTC 在玩家与房主间直连，无需等待 cpolar 返回结果。
- 网络无法直连或浏览器不支持 WebRTC 时，自动使用同一个 Node.js 服务通过 WebSocket 转发；没有额外 TURN 服务。
- 界面显示“P2P 直连”或“服务器转发”，房主显示直连/转发人数。直连后的毫秒数是浏览器间探测往返时间，并非单向延迟。
- 即使已经直连，也应保持 cpolar 运行；当前版本需要信令在线维护身份、加入、恢复及备份。
- 房主浏览器掌握全部对局信息，适合熟人局；普通玩家只收到自己的手牌、线索或投票视图。

详细设计、恢复边界及验证方式见 [P2P 说明](p2p.md)。

## 文件与配置

- 服务仅监听 `127.0.0.1:8787`，cpolar 只公开该端口。
- `work/rooms/` 存放房间身份与快照；写入采用临时文件后替换，服务重启后提供60秒恢复窗口。
- `work/cpolar/` 存放客户端及本机账号配置。整个 `work/` 被 Git 忽略，不公开分享。
- `work/local-host.json` 登记服务与隧道进程，停止时核对进程启动时间，避免误停其他程序。
- 旧运行时的数据保留但不再读取；此次迁移后需新建房间。
- 没有设置 Windows 服务或开机自启，没有购买套餐。

## 排错与验证范围

本地打不开时查看 `work/game-server.err.log`；公网打不开时查看 `work/cpolar/tunnel.out.log` 与 `tunnel.err.log`。

如果HTTPS长连接在当前网络不稳定，HTTP可用于临时排查，但其身份凭据与转发内容不受TLS保护；正式分享优先使用HTTPS。P2P直连本身也不保证在所有运营商、防火墙及NAT环境成功。

更换电脑时安装 Node.js 22.12+，执行 `npm ci`，从 cpolar 官方获取客户端并在本机配置账号。不要把账号密钥发进聊天或提交到仓库。

本机测试无法代表手机移动数据及不同运营商。分享前应实际测试手机打开网页、进入房间，以及界面显示直连还是转发。
