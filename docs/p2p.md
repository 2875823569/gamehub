# 房主主持的 P2P 联机

## 运行方式

网页默认以 `network: "p2p"` 创建房间。独立 Node.js 服务负责身份、成员、信令、转发与恢复快照，cpolar 提供该服务的公网入口。玩家通过可靠有序的 WebRTC DataChannel 连接房主，由房主运行共用规则引擎。服务端兼容 `network: "server"`，用于原有自动验收及需要本机服务器主持的客户端。

只有房主发起连接，避免多人同时协商冲突。信令服务根据已验证的 WebSocket 身份填写发送者，不信任客户端自报身份；普通成员只能与房主通信。连接编号与房主任期隔离刷新前的信令与旧房主消息。使用公开 STUN 服务发现网络候选；STUN 不承载游戏数据，无法穿透时使用 cpolar WebSocket 转发，不依赖 TURN 或额外付费服务。

## 操作、回退与隐私

- 操作包含请求编号。直连1500毫秒未确认时，经转发通道重试同一编号；主持引擎记住最近256个结果，恢复快照也包含这些结果，避免双重叫点、投票或结算。
- 状态带递增版本，普通玩家丢弃重复或过时视图。网络传输绑定已验证的玩家身份，不能在操作内容中指定另一个玩家。
- 数据通道使用有序可靠传输。发送积压、通道关闭、连接失败或探测超时会触发转发，后台继续尝试直连。
- 房主只向普通玩家发送 `view(playerId)`，不发送完整随机牌堆、其他人的骰子或未公开答案。
- 房主本身拥有完整数据，不能提供对房主的防作弊保证。创建房间时已说明这是适合熟人局的主持模式。
- 房主变更或正在游戏的成员离开时，本局结束；新房主可以重开。不会让新房主拿到已有全量秘密后继续原局。

## 恢复边界

每次状态变化先写房主标签页的 sessionStorage，再将完整快照异步备份到 Node.js 的 `work/rooms/`，并直接发布玩家视图。**正常操作不等待公网备份确认，但备份流量仍会经过 cpolar。**

刷新房主时，优先恢复同一身份、同一房主任期中版本较新的本地或服务器快照；普通玩家刷新向房主重新获取自己的视图。身份不会放进广播或P2P消息。

这不等同于强一致的持久化事务：若房主设备突然丢失本地存储，且最后几次操作尚未备份，可能回到最近服务器快照。房主退出/60秒断线后移交会结束正在进行的对局。不要把“操作已确认”解释为“异地备份已落盘”。

当前版本依赖协调连接维持在线身份；信令断开时暂停该客户端，自动重连后恢复。不要在直连成功后关闭本机服务或 cpolar。手机后台暂停可能延后房主计时器，恢复时仍按绝对截止时间拒绝逾期操作。

## 测试

启动 `npm start` 后：

```powershell
npm run check
npm test
npm run test:integration
npm run test:capacity
npm run test:party-integration
npm run test:rules-integration
npm run test:defuse-integration
npm run test:p2p
npm run test:p2p-protocol
```

浏览器验收默认使用本机 Edge 无头模式；设置 `GAMEHUB_BROWSER=chrome` 可改用本机 Chrome。`GAMEHUB_TEST_URL` 可覆盖默认 `http://127.0.0.1:8787`。

浏览器验收在独立上下文建立真实数据通道，验证私有手牌、直接操作、结算、双方刷新、房主移交、无 WebRTC 时转发。为避免外部 STUN 影响本地回归，测试关闭 STUN，只验证本机真实 WebRTC；公网 NAT 穿透和不同运营商延迟需要真实设备另行测量。

## 2026-11-10 验收

- 前后端 TypeScript 检查、生产构建通过；93项规则及主持引擎测试通过。
- 独立 Node.js 服务通过全部12款游戏的既有联机回归，包括六人容量、完整对局、观战、重连、私有视图、斋/飞/劈、单人及多人拆弹、60秒断线清理和服务端计时。
- Edge 两个独立浏览器上下文建立真实 WebRTC 通道，确认操作没有经过 WebSocket 转发；刷新双方恢复相同手牌。
- 注入通道丢包后，未收到的回复通过转发重试恢复，没有重复执行操作；禁用 WebRTC 时仍可入房并操作。
- 协议检查验证身份替换、旧连接信令隔离、跨玩家转发限制、普通玩家不可伪造主持消息或读取快照。
- 独立测试进程重启后，身份与恢复快照保留；房主离开后，新房主恢复快照并结束被中断的本局。
- 本机受管理服务已从旧运行时切换为 Node.js，现有 cpolar 隧道保持运行。公网 HTTPS 健康检查、创建/加入 P2P 房间及认证 WSS 转发均通过。
- 未验证不同运营商之间的真实 NAT 穿透成功率，未承诺具体延迟收益。
